What gets built next

The local board is live. The hosted one is not built yet, and neither is anything that needs the token.
Roadmapin order · no dates — —

poolitzer reads pons v2 launches on Robinhood Chain, scores them and ranks them. Today that happens on your own machine: you clone a repository and run a runtime, which rules out almost everybody. A hosted board is the next thing that matters, and it is not built.

Here is what gets built next, in order, with no dates. Anything marked planned above does not exist. If a page on this site ever describes something as working when it is not, that is a bug worth reporting.

01Make the score worth trusting

The graduation model is validated on time-ordered folds and reports what it actually did, including the folds where it did no better than chance. The peak model ranks well and sizes badly, so it is shown as an 80% band rather than as a number. Both improve with more settled history, which is what the backfills are for.

02Cover the history

Curves are read on demand, pools are swept wholesale, and enrichment has only covered the recent window. Every one of those gaps shows up as a dash somewhere on a card. The work is unglamorous and mostly spent waiting on rate limits.

03Make it reachable

A hosted board, then alerts. The local version stays free and stays the reference: the score you compute yourself is the score the site shows, which is the point of it being open.

04Never

xNever asks for a private key, a seed phrase or an approval.
xNever holds funds, never trades, never touches a wallet.
xNever sends your data anywhere. The local board talks to a public RPC and nothing else.
xNever presents a score as a safety rating, a price forecast, or advice.
xNever quietly drops a validation result for being unflattering.

05How to check

Commits show what shipped and when. The model page shows what the model scored on data it had not seen, and the scoreboard grades claims that were recorded before their outcomes existed. If something here goes quiet for weeks, ask about it in public.

Run it

Node >= 22.6 · no Python · no build step · no database to install
01Get the codeseconds
TypeScript runs directly on Node 22.6 and later, so there is nothing to compile.
$git clone https://github.com/Artemoon13/Ponscan-.git && cd Ponscan-
02Install and create the databaseunder a minute
Writes ./data/poolitzer.db and checks it can reach both endpoints. The defaults in .env work as they are.
$npm install && npm run setup
03Collect some historyminutes to hours
A model needs settled outcomes before it can be fitted. Backfill reads past launches; enrich fills in who created them and how much they self-bought.
$npm run backfill -- --hours 26
$npm run enrich-window -- --hours 20
04Fit the model and check ita minute
Trains on time-ordered folds and prints what it scored on data it had not seen. If that looks like chance, it says so.
$npm run train && npm run validate
05Open the board and start the watchernow
Two processes: the board serves this page, the watcher follows the chain and records every score before its outcome exists. Run them in separate terminals.
$npm run board
$npm run watch
06Keep it currentnightly
Backfill, enrich, read curves, follow pools, retrain, then fold old curves into summaries and reclaim the disk. The board reloads the model on every request, so a retrain needs no restart.
$npm run nightly

·Two endpoints, on purpose

Only the official RPC serves eth_getLogs, and it has no websocket. publicnode has the socket and faster state reads but refuses logs. So detection rides the socket, log reads go to the official node, and enrichment reads transactions from publicnode, which keeps the log budget with the watcher.

Both are public and neither needs a key. Measured over a day the whole thing costs about 133,000 requests, roughly 1.5 a second, against endpoints that start refusing near ten. A long bulk read earns a 403 eventually anyway; that is a request to slow down, and the reader waits it out rather than failing.

Telegram

One room, one bot.
Not built yet. There is no room and no bot today, and no $POOLITZER contract for either to be about. This page states what is planned, so the rules are on the record before anything exists. Anyone contacting you now claiming to be the poolitzer bot, the team, or support, is not.

The plan is a single room that acts as the tape: every $POOLITZER buy lands in it the moment it clears the pool, with the wallet, the size and the price. The bot answers questions in the room, and in a direct message it opens Pro for anyone who can prove the holding.

·What the bot will never do

xNever asks for a key, a seed phrase or an approval.
xNever messages anyone first.
xNever holds funds, never trades, never touches a wallet.

The holder check is a signature over a plain sentence, the kind every wallet can produce without spending gas, and the sentence says in words that it moves nothing.

·House rules

Nobody will ever message you first. Nobody will ever ask for your seed. No links to other tokens. There will be exactly one contract, published on the $POOLITZER page, and every other address carrying this name is not ours.

Pro

The terminal on your machine is free and stays free. Pro is the hosted half.
Not built yet. There is no hosted board, no holder check and no $POOLITZER contract. Nothing on this page can be bought, signed or unlocked today. It is here so the terms are visible before any of it exists.

The plan is that holding $POOLITZER opens the hosted site up: more watches at once, more live feeds, the heavy reads without a challenge, and creator history over any window. Proving the holding is a signature over a plain sentence. A signature has no chain, so the wallet can sit anywhere, and the site never asks for a key, a seed or an approval.

·What stays free, always

Everything you are looking at. The board, the card behind every launch, the model and its validation, the prediction log. You run it yourself, it talks to a public RPC and nothing else, and the score you compute is the score the hosted site shows. That is the point of it being open, and Pro does not change it.

·Where the fee goes

Every trade in the pool pays a fee, the pons hook routes the creator's share on-chain, and it lands wherever the launch pointed it. That routing is set at launch and is public; this is read from the launch itself, not from anyone's word about it.

·What this page does not show

No holder count, no liquidity, no 24-hour volume, and no price chart. None of those are indexed: the swap stream is folded to a running high, low and last per pool the moment it is read, because 3.4 million swaps a day pass through the singleton and keeping them all is what the disk cannot afford. Everything above comes from the launch record and that fold. A page people check before buying is the last place to start estimating.
